# 開発ログ記事の文体メモ

2026-11-09 のユーザー指示に基づく。既存記事の文体に寄せ、誤字・不正確な説明・偶発的な表記揺れは引き継がない。

参照: `u-pfkefj6zn0.md`、`2-q1jo80jo8.md`、`ndfryc-w8ws.md`、`34bpznogsn.md`。

- 基本はです・ます調。短い段落で具体的な変更や操作を説明する。
- 「〜してみました」「〜なんですが」「〜かなと」のような、率直で少しくだけた語尾を適度に使う。
- 「筆者」は時々使う程度。強い感嘆や絵文字は多用しない。
- 変更点は箇条書き、実際の画面は画像の前後で説明する。短い画像キャプションは平文でよい。
- 感想は具体的な体験として書く。未確認の成果や利用状況は作らない。
- 教訓を繰り返さず、最後は今後のことと「また次回」程度で自然に締める。
- 製品名・技術説明は正確にし、元記事の誤記や古い仕様は模倣しない。
- 見出し前後の装飾目的の区切り線は追加しない。画像の代替テキストは省略しない。

技術チュートリアルは開発ログと説明の密度が異なるため、この口調を機械的に当てはめない。
